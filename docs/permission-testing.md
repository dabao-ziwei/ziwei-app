# 權限接線與本機驗收

## 本次範圍

- 擁有者、學員、一般使用者使用共用的排盤權限判斷。
- 擁有者保留全部排盤功能；其他帳號依個別 ON / OFF，未指定則使用角色預設。
- 本次範圍內的功能：學員的排盤工具預設開啟，但截圖、紫微占卜、白板預設關閉；一般使用者全部預設關閉。吉凶占卜維持原有規則。
- 角色預設統一在 `src/logic/permissions.ts`，本次未新增角色預設編輯介面。
- 資料庫仍保留既有角色字串，擁有者沿用 admin，未進行資料遷移。舊的非擁有者 admin / competitor 在本次範圍內按一般使用者預設處理；個別功能設定保留。
- 吉凶占卜、排盤計算與命盤資料不變。白板改用功能權限，擁有者仍全開。
- 角色額度預設：一般會員 20 張／每盤修改 3 次，學員 200 張／每盤修改 5 次。
- 角色切換時帶入對應額度，可再手動調整，儲存後生效。讀取既有帳號仍保留已儲存的額度，缺值才採角色預設。
- 2026-10-11 已同步 Supabase 新註冊預設：一般會員 20 張／每盤修改 3 次、can_use_divination=false；保留原本一個月到期規則。學員額度於後台角色切換時帶入 200／5。
- 雲端腳本保存於 `supabase/migrations/202610110001_profile_signup_defaults.sql`。已回讀欄位預設與 `handle_new_user` 函式確認生效；交易內以 profiles 全列摘要確認既有會員資料未變更，未建立測試會員。

## 擁有者識別

在本機與部署環境設定 `VITE_OWNER_USER_ID` 為擁有者的 Supabase Auth User UID，重啟或重新建置後生效。
尚未設定時保留原 email 辨識，避免擁有者在確認 UID 前被鎖住。
UID 尚未確認，不能宣稱已完成固定 UID 綁定。

## 測試

1. 擁有者：所有本次範圍的功能即使 OFF 仍可用，後台可進入。
2. 一般 / 學員：開關直接顯示有效狀態（綠色／滑塊向右＝開，灰色／向左＝關）；點一下切換，儲存後重新進入單人盤與合盤驗證。
3. 流月 / 流日：一般帳號設 ON 後可使用；仍遵守原本先選流年、流月等操作條件。
4. 合盤：兩邊同時依登入者權限控制雙胞胎、顛倒盤、小限、流月、流日。
5. 關閉功能後切回網站或重新整理：入口消失，相關顯示狀態清除。
6. 無權限時進入合盤、紫微占卜或後台路由：不掛載功能，返回首頁。
7. 非擁有者的列表不掛載使用者管理元件，也不可授予其他管理員身分。
8. 白板：ON 時在單人盤與合盤可使用，OFF 時入口及畫布移除。使用中撤銷權限，切回網站後退出書寫模式。
9. 角色切換一般會員／學員，確認額度為 20／3 與 200／5，尚未儲存時不更動雲端資料。

自動測試：`node --test tests/*.test.mjs`；建置：`npm run build`。

## 邊界

本次為網站端功能與管理入口的權限接線，加上新會員雲端預設同步；未變更雲端資料庫 RLS、吉凶占卜與計費服務。
前端判斷不能取代資料庫授權；雲端資料的防越權仍需另行驗證。
Supabase Dashboard 已確認 profiles 與 clients 的 RLS 為 DISABLED；啟用前須先審核既有 policy 與管理權限，以免造成存取失敗。本次未切換。
